# PeppolSG.API – Deployment & Operations Guide

## Build Artifacts
The application is delivered as an IIS web site (ASP.NET 4.8). CI pipeline should produce:
- WebDeploy package (`PeppolSG.API.zip`).
- XML doc files for swagger (generated by build).
- Test results and code coverage report.

## Environments
| Environment | URL | APP_ENV | Notes |
|-------------|-----|---------|-------|
| Development | http://localhost:5000 | Development | IISExpress, self-signed certs |
| Test        | https://test.ap.acc.sg | Test | Secured by Let's Encrypt |
| Production  | https://as4.peppol.sg | Production | HSM-backed certificate |

## Configuration
All settings reside in *Web.config* `<appSettings>` and are managed by ConfigurationService.
Sensitive values are stored as `...Encrypted` base64 strings.

| Key | Description |
|-----|------------|
| PeppolP12FilePath | Absolute path to Peppol PKI certificate |
| PeppolP12PasswordEncrypted | DPAPI-encrypted certificate password |
| IsTestEnvironment | `true` for sandbox/test deployments |
| AlertEmail | Email to notify on critical alerts |

## Deployment Steps (WebDeploy)
1. Stop site: `appcmd stop site PeppolSG.API`.
2. Execute package: `msdeploy -verb:sync -source:package=PeppolSG.API.zip -dest:auto,computerName="..."`.
3. Start site: `appcmd start site PeppolSG.API`.
4. Verify `/api/health/readiness` returns `status=Ready`.

## Zero-Downtime Strategy
Use two IIS sites behind a load-balancer:
1. Drain instance A, deploy, health-check, put back into LB.
2. Repeat for instance B.

## Logging & Monitoring
- Log4net writes rolling JSON logs to `logs/structured-yyyyMMdd.log`.
- Ship logs with Filebeat to ELK or Splunk.
- Health endpoints are polled by Prometheus.
- Alerts are sent via `AlertingService` integration.
